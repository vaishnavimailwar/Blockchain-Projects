1. Blockchain Fundamentals

A blockchain is an ordered, append-only list of blocks where every block cryptographically references the one before it. Here, blockchain.py implements exactly this structure from scratch in pure Python.

2. Decentralized Ledger Concept

Every issued certificate is treated as a permanent ledger entry. Instead of a central mutable "certificates" table, each record becomes an immutable block, mirroring how a distributed ledger records transactions.

3. Append-Only Data Structure

New certificates are only ever added to the end of self.chain via add_certificate(). Existing blocks are never edited during normal operation.

4 & 7. Blocks & Block Structure

Each block is a JSON object containing: index, timestamp, certificate data, certificate hash, Merkle root, previous hash, and current hash — visible directly in the Explorer.

5. Blockchain Architecture

Flask (app.py) handles requests and rendering; blockchain.py is a self-contained ledger engine; JSON files provide persistence. This separation mirrors how real blockchain nodes separate application logic from ledger storage.

6. Genesis Block

The very first block (index 0) is created automatically the first time the app runs, with a fixed previous hash of 64 zeros. It is clearly marked in the Explorer and can never be tampered with in this demo.

8. Block Index

Every block has a strictly increasing index field, starting at 0, giving each block a unique, ordered position in the chain.

9. Timestamp

Every block records the exact date and time it was created using datetime.now(), providing an auditable creation record.

10. Certificate Data / Transactions

The certificate fields (student name, USN, course, title, issue date, certificate ID, and optional file hash) act as the "transaction" payload carried inside each block.

11. SHA-256 Hashing

SHA-256 is used everywhere: hashing certificate data, computing Merkle leaves, computing the final block hash, and hashing the raw bytes of any uploaded certificate file.

12 & 13. Current Hash & Previous Hash

Each block stores its own current_hash and the previous_hash copied from the prior block, forming the cryptographic chain.

14. Chain Linking

Because each block's previous_hash must equal the prior block's current_hash, changing any block breaks the link to every block that follows it — this is what makes the structure a "chain".

15. Immutability

Any edit to a block's certificate data changes its hash, which breaks the link to later blocks. This makes silent, undetected edits practically impossible — the core promise of blockchain immutability.

16. Tampering Detection

The Tampering Demo page lets you directly edit stored certificate data. validate_chain() immediately flags the mismatch between the data and its recorded hash. File-based tampering is caught the same way: any change to the certificate file bytes changes its SHA-256 hash on re-verification.

17. Chain Validation

validate_chain() re-computes every hash and every link for the entire chain and reports exactly which block(s) failed and why — shown live in the Explorer and Tampering Demo.

18. Merkle Tree Concept

Each block's certificate fields are individually hashed as "leaves", then paired and hashed together repeatedly until a single Merkle Root remains, via compute_merkle_root(). This demonstrates how Merkle trees let large amounts of data be summarized into one fixed-size fingerprint.

19. Document / File Integrity Verification

Beyond text data, the project extends hashing to real files: an uploaded certificate's raw bytes are hashed with SHA-256 at issue time and stored on-chain, then re-hashed at verification time. Any modification to the file — even a single changed pixel or byte — produces a completely different hash, instantly exposing forged or altered certificate documents.
